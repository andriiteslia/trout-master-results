# Trout Master: онлайн-результати змагань

Сторінка показує результати турніру з Google Таблиці й сама перевіряє оновлення кожні 20 секунд. Глядачам не треба нічого перезавантажувати.

```
Google Таблиця  →  Apps Script (віддає JSON)  →  сайт на GitHub Pages
```

## Що в репозиторії

| Файл | Навіщо |
|---|---|
| `index.html`, `assets/` | Сам сайт (розмітка, стилі, скрипт, шрифти) |
| `config.js` | Налаштування: адреса Apps Script, назва, частота оновлення |
| `demo.json` | Демо-дані. Сайт показує їх, поки в `config.js` не вставлено адресу Apps Script |
| `apps-script/Code.gs` | Код для Apps Script, який читає таблицю |

## 1. Налаштувати Apps Script (один раз, близько 5 хвилин)

1. Відкрийте [script.google.com](https://script.google.com) і натисніть **«Новий проєкт»**. Назвіть його, наприклад, «Trout Master API».
2. Видаліть усе з файлу `Code.gs` і вставте вміст файлу `apps-script/Code.gs` з цього репозиторію. Збережіть (Cmd+S).
3. Зліва натисніть ⚙ **«Налаштування проєкту»**, прокрутіть до **«Властивості скрипту»** → **«Додати властивість скрипту»**.
   - Властивість: `SPREADSHEET_ID`
   - Значення: посилання на таблицю турніру (можна повне посилання, можна лише ID)
   - **«Зберегти властивості скрипту»**
4. Поверніться в **«Редактор»**, угорі у списку функцій виберіть `testConnection` і натисніть **«Виконати»**. Google попросить дозвіл: **«Переглянути дозволи»** → ваш акаунт → **«Розширені»** → **«Перейти до Trout Master API (небезпечно)»** → **«Дозволити»**. Попередження стандартне для власних скриптів. У журналі виконання мають з'явитися назви листів таблиці.
5. **«Розгорнути»** → **«Нове розгортання»** → ⚙ біля «Виберіть тип» → **«Веб-застосунок»**.
   - Виконувати від імені: **Я**
   - Хто має доступ: **Усі**
   - **«Розгорнути»** і скопіюйте **URL веб-застосунку** (закінчується на `/exec`).
6. Відкрийте цей URL у браузері. Має з'явитися текст, що починається з `{"ok":true`.
7. Вставте URL у файл `config.js` у поле `API_URL` (на GitHub: відкрити файл → ✏️ → вставити → Commit changes). За хвилину сайт почне показувати живі дані.

## 2. Новий турнір

Змініть значення властивості `SPREADSHEET_ID` на посилання нової таблиці (крок 3). Більше нічого робити не треба: ні перерозгортати скрипт, ні змінювати сайт. Сайт перейде на нову таблицю протягом пів хвилини.

Порада: робіть таблицю нового турніру копією попередньої (Файл → Створити копію), тоді структура гарантовано буде та сама.

## 3. Якою має бути таблиця

- Кожен **видимий лист** стає вкладкою на сайті. Приховайте лист або колонку в таблиці, і вони зникнуть із сайту.
- **Перший рядок** містить назву турніру. Текст у дужках у кінці назви стає підзаголовком: «(3-4 жовтня, 2026 рік)».
- Далі йдуть **один або два рядки заголовків**. Об'єднані клітинки над колонками («1 день», «2 день», «Загалом») стають групами. Остання група вважається підсумковою: вона виділена, а її перша колонка напівжирна.
- **Дані** починаються з першого рядка, де в колонці A стоїть число (місце).
- Текст у дужках після назви команди чи імені показується дрібно під нею (федерація).
- Кількість днів і колонок може бути будь-якою, сайт підлаштується.

## 4. Що бачать глядачі

- Вкладки заліків: командний, особистий.
- На телефоні є перемикач «1 день / 2 день / Загалом / Усе», щоб таблиця не була надто широкою.
- Пошук за іменем або назвою команди.
- Якщо торкнутися імені, рядок учасника закріпиться над таблицею (запам'ятовується в браузері глядача).
- Після кожного оновлення стрілки ▲ і ▼ показують, хто скільки місць виграв чи втратив, а змінені клітинки на мить підсвічуються.
- Угорі видно статус «Оновлено о 14:32», тобто час останньої зміни в таблиці. Якщо зв'язок зник, сторінка показує останні отримані дані й попередження.

## Якщо змінюєте код Apps Script

**«Розгорнути»** → **«Керувати розгортаннями»** → ✏️ → Версія: **«Нова версія»** → **«Розгорнути»**. Адреса `/exec` залишиться та сама. Якщо натиснути «Нове розгортання», адреса зміниться і її доведеться оновити в `config.js`.

## Ліміти

Готова відповідь кешується на 10 секунд, тому таблиця читається не частіше разу на 10 секунд, хоч би скільки людей дивилися сайт. Для кількох десятків глядачів квот Apps Script вистачає з великим запасом.

## GitHub Pages

Settings → Pages → Source: **Deploy from a branch** → гілка `main`, папка `/ (root)`.
